# Documentation Instructions

Follow the repository-level `AGENTS.md` in addition to these documentation
rules.

- Update documentation in the same change as user-visible behavior or public
  contracts.
- Describe current behavior; keep proposals clearly marked as proposals.
- Put architecture decisions in `docs/architecture/` with context, decision,
  alternatives, and consequences.
- Include inputs, outputs, errors, and a minimal example for every public tool
  and agent contract.
- Prefer links to one canonical explanation over copying text between pages.
- Keep diagrams consistent with implemented routing and dependency direction.
- Use relative links for repository documentation.
- Verify the MkDocs build before submitting documentation changes.
- Never include credentials, private datasets, internal URLs, or user data.
